## 2. Route-by-Route Findings & Endpoint Mapping

### 2.1 Critical Discovery: Python Decorator Evaluation & `url_for()` Resolution
In Python, multiple decorators on a single function are evaluated **bottom-to-top**. Consequently, when Flask registers multiple routes for a single view function, the rule registered first in Flask's internal `_rules_by_endpoint` table determines what `url_for()` outputs by default.

A live runtime inspection inside the Flask application context revealed the **exact** URL resolution for all key routes:

| Flask Endpoint | Route Decorators in `routes/main.py` | Rules in `_rules_by_endpoint` (First = Default) | Actual `url_for()` Output | Live HTML Link on Production Homepage |
|---|---|---|---|---|
| `main.products` | `@route('/product')`<br>`@route('/products')` | `['/products', '/product']` | `/products` | `<a href="/products">` |
| `main.contact` | `@route('/contact')`<br>`@route('/contact/')` | `['/contact/', '/contact']` | `/contact/` | `<a href="/contact/">` |
| `main.privacy` | `@route('/privacy')`<br>`@route('/privacy-policy')` | `['/privacy-policy', '/privacy']` | `/privacy-policy` | `<a href="/privacy-policy">` |
| `main.terms` | `@route('/terms')`<br>`@route('/terms-and-conditions')` | `['/terms-and-conditions', '/terms']` | `/terms-and-conditions` | `<a href="/terms-and-conditions">` |
| `main.refund_policy` | `@route('/refund-policy')`<br>`@route('/cancellation-refund')`<br>`@route('/refunds')` | `['/refunds', '/cancellation-refund', '/refund-policy']` | `/refunds` | `<a href="/refunds">` |
| `main.profile` | `@route('/profile')`<br>`@route('/my-profile')` | `['/my-profile', '/profile']` | `/my-profile` | `/my-profile` |

## 4. API & Webhook Inspection for `robots.txt`

The complete Flask application route map was inspected for API and webhook endpoints. Four distinct non-HTML / transactional endpoints were verified:

1. `/api/health` (`health_check` [GET]): Public uptime and diagnostic health check endpoint.
2. `/api/contact` (`contact.api_contact` [POST]): JSON endpoint for contact form inquiries.
3. `/api/contact/` (`contact.api_contact` [POST]): Slash variant of contact API.
4. `/payment/cashfree/webhook` (`main.cashfree_webhook` [POST]): Cashfree server-to-server payment notification webhook.

### Implications for `robots.txt`:
- Search engine spiders have no reason to crawl `/api/` or `/payment/cashfree/webhook`.
- Setting `Disallow: /api/` in `robots.txt` is 100% safe and will prevent crawlers from hitting backend diagnostic or API submission routes.
- Cashfree webhooks are server-to-server POST calls that do not read `robots.txt` and are CSRF-exempted.

## 7. Deployment Workflow & Safety Guard Verification

### 7.1 GitHub Actions Workflow (`.github/workflows/deploy.yml`)
Inspection of lines 68–79 in `.github/workflows/deploy.yml` confirmed:
```bash
rsync -az \
  --exclude='/.env' \
  --exclude='/.env.*' \
  --exclude='/.venv/' \
  --exclude='/app.py' \
  --exclude='/*.predeploy-*' \
  --exclude='/.git/' \
  --exclude='/.github/' \
  --exclude='/.gitignore' \
  -e "ssh -i $HOME/.ssh/anti_matrix_key -o IdentitiesOnly=yes -o BatchMode=yes" \
  ./ "$VPS_USER@$VPS_HOST:/var/www/anti-matrix/"
```
- **`rsync --delete` is NOT used.** Existing files on the VPS are preserved.
- **`/app.py` is EXPLICITLY EXCLUDED.** The production `app.py` on the VPS is never overwritten by GitHub pushes.
- **`.env` is EXCLUDED.** Production secrets and Supabase credentials cannot be overwritten.
- **Deployment Trigger:** App restart is executed by `sudo -n /usr/local/bin/anti-matrix-deploy`.

### 7.2 Production Startup Guard (`ALLOW_STARTUP_DB_INIT=false`)
- On the Hostinger VPS, `/var/www/anti-matrix/app.py` enforces:
  `ALLOW_STARTUP_DB_INIT=false`
  preventing any automatic `db.create_all()` or schema resets on startup.
- **Implementation Alignment:** Because `deploy.yml` excludes `app.py`, **any new application context processors or canonical logic must be registered inside `routes/main.py` using `@main_bp.app_context_processor`**. This ensures the change deploys cleanly without modifying or replacing `app.py`.
